# tkOrders: data binding and designed reports over SQLite

A small customer-and-orders program made in **tkEdit's Form Designer** and **Report Designer**. It shows
data binding end to end, from an SQLite database to the screen and back, and then onto paper:

- records read from SQLite, bound to controls, stepped through with a **Navigator**, listed and edited
  in **DataGrids**, and written back;
- three **designed reports**, one for each way a report gets its data: an array of records, an SQL
  query, and a DataGrid on a form.

The tutorial that builds it step by step is the wiki's
[Orders Tutorial](https://github.com/PaulSquires/tiko-lang/wiki/Orders-Tutorial)
(`wiki/Orders-Tutorial.md` in this repository).

## Run it

Open this folder in tkEdit (it is a project: `tiko.toml`) and build the `orders` target, or from a shell:

```
tiko build orders
orders.exe
```

On first start it makes `orders.db` in your data folder (`%APPDATA%\tkOrders\` on Windows) and fills it
with the sample data: **25 customers, 16 products, 100 orders, 242 order lines** (all names made up).
Delete the file to start again.

`tiko build selftest` + `selftest.exe` runs the self-test against a database of its own in a temp folder.

## What's where

| Path | What it is |
| --- | --- |
| `frmCustomers/` | The main window. `.tkform` = the design, `.design.tiko` = generated (don't edit), `.tiko` = the code you write. |
| `frmOrders/` | Every order in one grid that **is** an SQLite query. **Print list...** prints it. |
| `frmOrder/` | The order dialog: header fields + a live lines grid. **Invoice...** shows the order as an invoice. |
| `frmInvoice/` | A ReportViewer whose report is `rptInvoice` (the form's `rvInvoiceReport` member). |
| `frmReport/` | A ReportViewer for any report: the caller makes the report and shows it here. |
| `rptInvoice/` | The invoice: an **array** source (`orderdb.Order`) with a child source (its `Lines`). |
| `rptSales/` | Sales by customer: an **SQLite** source with two date parameters, grouped, with totals. |
| `rptOrderList/` | The order list: a **grid** source, `frmOrders`' grid as the user filtered and sorted it. |
| `orderdb/orderdb.tiko` | The records (`Customer`, `Order`, `OrderLine`, `Product`) and every SQL statement. |
| `orderdb/seed.tiko` | The sample data, generated by `tools/makeseed.py` (deterministic). |
| `appTheme/` | The project theme (`.tktheme`, generated module). |
| `askbox/` | A message box in the form's fonts (from the tkContacts example). |
| `selftest.tiko` | The self-test: the forms, and the reports' text against SQLite's own counts and sums. |

A `.tkreport`'s generated `.design.tiko` embeds the report file (`#embed`): after editing a report,
regenerate (tkEdit does it on save) and rebuild.

## What each form shows

**frmCustomers**: `DataType = orderdb.Customer`

- **Bound controls of every common kind**: TextBox (Company is *Required*), ComboBox (Tier, its items
  from `orderdb.Tiers( )`, DisplayField / ValueField), DatePicker (`chrono.LocalDate`), NumericUpDown
  (`float64`), Rating, CheckBox. The generated `LoadFrom` / `SaveTo` / `IsDirty` move them.
- **Navigator** `navCustomers`, `ItemsSource = Customers`, **follows** the `grdCustomers` grid.
- **DataGrid bound to the form's list** (`grdCustomers`, `ItemsSource = Customers`).
- **DataGrid bound to a field of the record** (`grdOrders`, `ItemsField = Orders`), with a footer
  count and sum.
- **Saving like a classic data form**: moving to another customer saves the one you left (`Commit` /
  `WriteChanges` in `frmCustomers.tiko`).
- **Sales report...**: `rptSales` in the report window.

**frmOrders**: the grid is a query (`tkDataGridSqlite`): sorting is `ORDER BY`, the filter row a
`WHERE`, the footer `select count / sum`. **Print list...** prints exactly the rows on show.

**frmOrder**: `DataType = orderdb.Order`. A **live** lines grid (`ItemsField = Lines`, `items_live`),
a method column (`Total( )`), money with two decimals through **CellFormatting** and
**SummaryFormatting**. **Invoice...** prints what the dialog shows, without saving it.

## The reports

| Report | Source kind | The program gives it | Shows |
| --- | --- | --- | --- |
| `rptInvoice` | `array`, with a child `array` | `SetOrders( Array( of orderdb.Order ) )` | one order, its lines sorted by product, a calculated `LineTotal`, the total |
| `rptSales` | `sqlite`, parameters `:FromDate` / `:ToDate` | `SetDatabase( orderdb.Connection( ) )` | orders grouped by customer, a sum per customer and in all; Open orders in amber |
| `rptOrderList` | `grid` | `SetOrdersGrid( grdAll.Handle )`, `Filters = ...` | the grid's rows in its order, a count and a sum |

## Editing the forms and reports

Open a `frm*/frm*.tkform` or `rpt*/rpt*.tkreport` in tkEdit to see it on the design surface; saving
regenerates its `.design.tiko`. From a shell: `tkedit --generate-forms <this folder>` (writes what
differs) or `tkedit --check-forms <this folder>` (reports drift).

## Notes

- **One tiko link trap.** `frmOrders.tiko` and `frmCustomers.tiko` have `#import "vendor/sqlite3"` even
  though `orderdb` already re-exports it. Without it the build fails at link time (`undefined symbol
  ...SETDATABASE(SQLITE3*)`): an opaque C type such as `sqlite3` that a module only sees through
  another module's `#import ... public` is mangled differently from the module that defines the
  procedure. Importing it directly fixes it.
- **A report parameter becomes a field of the generated report**, so it can't be named like a keyword
  (`To`): the Report Designer's Parameters dialog refuses it. Hence `FromDate` / `ToDate`.
- **A DataGrid "number" column is `float` to a report**, whatever the database column was: the grid
  source's field `Order` is `kind = "float"`, printed with `format = "0"`.
