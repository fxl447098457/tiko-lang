# TIKO'S OWN RULE for a DECLARE and its definition, and where it parts company with fbc.
#
# THE RULE: a declaration that names no convention takes CDECL, and a definition that
# names one must match. Absence on the DEFINITION inherits whatever the declaration said.
#
# FBC'S RULE (tests/types/expected/fbc-callconv.txt, measured from fbc 1.10.1 on win64,
# 2026-11-23) treats absence as STDCALL, so two pairings differ:
#
#   declare (none) + definition cdecl     fbc rejects, tiko accepts
#   declare (none) + definition stdcall   fbc accepts, tiko rejects
#
# That is a DELIBERATE divergence, and this file is where it is recorded: the default
# calling convention is cdecl on every target (symbols/collecthelp.tiko's Effective_,
# and ParserState.fbcallConv), which is GCC's convention and the one the MinGW targets
# use. Off Windows fbc's default is cdecl too, so tiko's rule is fbc's there; on Windows
# x86-64 fbc's own default is stdcall and the two conventions are the same code anyway.
#
# The rule is SYNTACTIC and not an ABI one: on x86-64 stdcall and cdecl are the same
# calling sequence, and the only target where the difference shows is win32, where the
# convention decides the '@N' decoration of the name.
none	none	accept
none	cdecl	accept
none	stdcall	reject
none	pascal	reject
cdecl	none	accept
cdecl	cdecl	accept
cdecl	stdcall	reject
cdecl	pascal	reject
stdcall	none	accept
stdcall	cdecl	reject
stdcall	stdcall	accept
stdcall	pascal	reject
pascal	none	accept
pascal	cdecl	reject
pascal	stdcall	reject
pascal	pascal	accept
